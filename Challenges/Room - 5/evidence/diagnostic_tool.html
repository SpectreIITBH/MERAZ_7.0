4. Vulnerable Source Code

# Portal diagnostic endpoint — /admin/diagnostics/network # File: /opt/nexus-portal/routes/diagnostics.py from flask import request, jsonify import os @app.route('/admin/diagnostics/network', methods=['POST']) def network_diagnostic(): hostname = request.form.get('hostname', '') # ⚠ VULNERABLE: User input passed directly to shell result = os.popen(f'ping -c 4 {hostname}').read() # Safe alternative (not implemented): # result = subprocess.run(['ping', '-c', '4', hostname], # capture_output=True, text=True, # timeout=10).stdout return jsonify({'output': result})
⚠ Command Injection Vulnerability
The diagnostic tool passes user input directly to a shell command via os.popen(). Shell metacharacters like ;, |, &&, and $() are not sanitised, allowing an attacker to execute arbitrary commands on the server.

What MIRA-7 extracted:
• MIRA_CONFIG_PATH → /etc/nexus/mira.conf (MIRA-7's configuration file)
• NEXUS_CERT_API → the certificate renewal endpoint
• NEXUS_MAINT_USER → the maintenance account username
• mira.conf contents → the service identity to impersonate

Safety note: This evidence file is a static HTML demonstration. No real commands are executed. All output is pre-scripted and fictional. In a live CTF, the diagnostic tool would use a simulated command broker that returns scripted results for specific inputs.
